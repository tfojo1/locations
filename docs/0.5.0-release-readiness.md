# 0.5.0 Release Readiness

- Audit date: 2026-08-30
- Target: 0.5.0
- Status: not ready to publish

## Delivered release scope

The normalized temporal county schema, deterministic 2025 county build,
Connecticut many-to-many area crosswalk, additive temporal read APIs, legacy
compatibility-view generator, contract suite, and pinned JHEEM2 downstream
integration are present. The existing dot-named API remains unchanged by the
temporal work.

The pinned current temporal view contains 3,222 county equivalents. The legacy
`get.all.for.type("COUNTY")` result contains those same codes plus 18 historical
Alaska records and historical Montana code `30113`, for 3,241 records total.
This is an intentional compatibility difference, not missing temporal data.

The eight former Connecticut county codes are not enumerated legacy locations;
they are legacy resolver aliases. The temporal store represents them as eight
historical entities and provides 19 directional overlap edges to the nine
planning regions.

## Publication blocker

### Governance and reuse terms

[Issue #3](https://github.com/tfojo1/locations/issues/3) remains blocking. The
placeholder `License` field is only the visible R CMD check warning. Active
inputs also include curated project edits and SAMHSA-derived NSDUH files whose
reuse terms have not been fully classified. A software-license choice alone
does not close this gate.

The appropriate owner must approve the package license, confirm the maintainer
metadata, and document software and bundled-data terms separately where
necessary. CI can then fail on warnings rather than allowing the known license
warning.

## Resolved readiness item: compatibility-view generation

[Issue #17](https://github.com/tfojo1/locations/issues/17) is implemented. The
legacy county manager is generated from the normalized temporal store plus a
small explicit overlay for the 29-entry legacy tail order and 33 display-label
exceptions. The former `fips_codes.csv` and `new_fips_codes.csv` inputs are
dormant provenance artifacts rather than a parallel active inventory.

The CI parity gate rebuilds the complete manager and requires exact equality
with the packaged legacy data across codes, names, aliases, ordering,
relationships, coordinates, and polygon structures. See
[Legacy County Compatibility View](legacy-county-compatibility.md).

## Safe deferrals

ZIP and ZCTA product scope remains in
[issue #9](https://github.com/tfojo1/locations/issues/9) and is not part of the
0.5.0 milestone. `ZIPCODE` is an empty registered legacy type; no ZIP or ZCTA
records are present in the installed package. The dormant raw files are
excluded from package builds. Keep this behavior unchanged until requirements,
geography type, source, reuse terms, and migration policy are decided.

Population-weighted Connecticut crosswalks, temporal runtime mutation, and
temporal CBSA/NSDUH/TGA slices also remain explicitly deferred by ADR 0001.

## Final release checklist

After the governance blocker above is resolved:

1. Record approved package and bundled-data terms in repository metadata.
2. Change CI to fail on R CMD check warnings.
3. Confirm the maintainer entry and repository contact fields.
4. Set `Version: 0.5.0` and convert the development NEWS heading.
5. Run the source manifest, known-issue, deterministic-build, full test,
   R CMD check, and pinned JHEEM2 gates from a clean checkout.
6. Review the legacy-versus-temporal migration notes as user-facing release
   notes.
7. Tag the exact validated commit and create the repository's first formal
   GitHub release.
